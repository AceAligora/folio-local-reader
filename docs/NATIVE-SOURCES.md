# Folio-native sources

Folio adapters are reviewed JavaScript services shipped with the app. They never execute downloaded third-party code. `lib/source-registry.mjs` declares bundled versions, capabilities, approved hosts and validated source-specific settings; `lib/native-sources.mjs` implements requests/imports. Android APK repositories remain discovery/package caches, as selected by the user.

## Bundled sources and lifecycle

- **Gutenberg v2:** [Gutendex](https://gutendex.com/) search with language filter, popularity/ID ordering and 32-result catalogue pages. Downloads are explicit EPUB imports. Existing v1 profiles retain their source switch and first-page search; activate the bundled v2 update for preferences and pagination.
- **Open Library v1:** [Search API](https://openlibrary.org/dev/docs/api/search) work discovery, relevance/publication ordering, preferred edition language, and 8/16/32-result pages. Only selected fields are requested. Language preference influences ranking and is not a hard filter. Results provide details links and explicit metadata application to a local book; they do not grant borrowing access or provide ebook downloads.

Add/remove/update changes a local record of bundled versions and settings, without contacting a server. Removing a source retains local books, caches and settings; re-adding it restores preferences. New code arrives through Folio updates. Unknown adapter IDs and arbitrary hosts/code are rejected. Adapter configuration is stored in the profile database and included in full-profile archives.

Discovery caches include source, query, page, language, sort and page size, with opaque tokens binding displayed results to later download/metadata actions. A token from another source/query cannot be substituted. Existing Gutenberg cache entries remain readable for default first-page searches. Cached data can be read even with a source disabled/removed or networking off. Search preference changes require the corresponding cached combination, or a fresh explicit online search. Online results are reused for 24 hours unless explicitly refreshed; requests are paced at two seconds. Pagination constructs service URLs locally and never follows catalogue-provided next links.

Adapters declare an identifier, version, formats and approved HTTPS hosts, cache discovery locally, and use `Imports` for explicit downloads. Known downloads are deduplicated per library/source identifier. Alternative editions remain separate books because page locations can differ.

`NetworkServices.bounded` enforces network opt-in, HTTPS, approved hosts on every redirect, timeouts and response-size limits. Search sends user-entered text only. Cached discovery stays readable with network disabled. Downloads never overwrite originals.

## Source checks and refresh

`lib/source-updates.mjs` persists links/reviews in `source_updates`. It recognizes source-owned metadata by canonical IDs and records download bindings. Open Library checks use a work-ID search (the documented [Search API](https://openlibrary.org/dev/docs/api/search)); Gutenberg checks use its individual-book endpoint. A review contains the observed metadata, approved cover reference, edition link, revision fingerprint and local metadata/cover baseline. Explicit apply rejects stale local baselines. Manual metadata remains review-only even when automatic source-owned refresh is selected.

Cover references come from [Open Library Covers](https://openlibrary.org/dev/docs/api/covers) numeric IDs or approved Gutenberg image paths. Downloads are limited to 5 MB, checked for supported image signatures, and stored through `CustomCovers` using an optimistic expected-cover guard. Open Library images may redirect to `archive.org` and HTTPS numbered storage hosts matching `ia` plus six digits under `archive.org` or `us.archive.org`; other hosts remain blocked. No cover crawling or unrestricted remote proxy is provided.

Checks require both networking and non-Incognito operation, honor source enablement, folder/category exclusions and per-link pause state, and can be cancelled through abort signals. Background work requires a saved opt-in, runs without a browser, and checks at most 10 oldest-due links per pass, two seconds apart. Errors keep the last successful observation/review. Full-profile archives include links, pending reviews and managed-cover ownership. Reading-data restore preserves current automatic apply choices.

Manual content comparisons are a separate saved opt-in plus an explicit action for one linked book. The first successful comparison records a SHA-256 baseline for the approved EPUB/cover reference; subsequent comparisons detect changed bytes at unchanged URLs. Limits are 20 MiB per EPUB and 5 MiB per image. Signatures reject unexpected HTML/challenge responses; these checks are format screening, not full EPUB/image validation. Only digests, byte counts, URLs and comparison dates are retained. Regular/background checks reuse baselines without downloading assets for comparison. A reviewed cover is downloaded again on apply and its digest must still match. Book files, notes and positions are never replaced or copied by this feature. Paused/excluded/unavailable links, removed/disabled adapters, network-off and Incognito reject comparisons. Cancellation or a failed comparison preserves the successful baseline/review. Restore of reading-data JSON preserves the current comparison choice.

Manual comparisons avoid periodic whole-file polling against [Gutenberg's automated-access guidance](https://www.gutenberg.org/policy/robot_access.html) and [Open Library's cover-use guidance](https://openlibrary.org/dev/docs/api/covers). A digest change may reflect Gutenberg's format regeneration, not a chapter update. Users obtain updated editions separately through source details.

Gutenberg/Open Library remain complete-edition/work adapters. The separate bundled Chapter feeds adapter adds author-published RSS/Atom series, explicit chapter EPUB downloads and optional background feed checks. Source requests are stateless by default; opt-in Desktop sessions can explicitly share temporary cookies in memory. There is no automatic challenge bypass, original-chapter replacement or arbitrary image-folder tracking. See [chapter feeds and sessions](CHAPTER-FEEDS-AND-SESSIONS.md).

New adapters require fixture tests for offline behavior, address restrictions, malformed data, limits and unchanged originals. Keep credentials, books and profile files out of the repository. Observe source access rules and licensing. Folio uses catalogue searches and explicit, paced downloads; see [Gutenberg access guidance](https://www.gutenberg.org/policy/robot_access.html).
